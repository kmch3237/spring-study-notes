■ MyUtil이란?
  → 게시판 전체에서 반복적으로 쓰이는 공통 기능 모음 클래스.
  → 직접 비즈니스 로직을 처리하는 건 아니고,
    "한글 URL 인코딩", "XSS 방어", "이름 마스킹" 같은 잡일을 대신 해주는 도구.

  비유: 공사 현장의 공구함. 없으면 일 못 하지만 공구함 자체가 건물을 짓지는 않는다.

■ 파일 위치: com.doit.app.common.MyUtil

 [1] @Service — 스프링 빈으로 등록
====================================================================

  @Service
  public class MyUtil { ... }

  → @Service를 붙이면 스프링이 이 클래스의 객체를 자동으로 만들어 관리한다.
  → BoardController에서 생성자 주입으로 받아 사용:

    public BoardController(BoardService boardService, MyUtil myUtil, ...) {
        this.myUtil = myUtil;
    }

  ★ @Component / @Service / @Repository 차이 (역할 구분용 어노테이션)
  ┌─────────────┬────────────────────────────────────────────┐
  │ @Component  │ 일반 컴포넌트 (기본)                        │
  │ @Service    │ 비즈니스 로직 담당 클래스에 사용             │
  │ @Repository │ DB 접근 클래스(DAO, Mapper)에 사용          │
  │ @Controller │ 요청 처리 컨트롤러에 사용                    │
  └─────────────┴────────────────────────────────────────────┘
  → 기능 차이는 거의 없지만 역할을 명확히 표현하기 위해 구분해서 씀.
  → MyUtil은 유틸이지만 서비스 빈으로 등록해서 @Service 사용.

 [2] URL 인코딩 & 디코딩 (한글 검색어 처리)
====================================================================

  왜 필요한가?
  → URL에 한글이 그냥 들어가면 서버에서 깨지거나 에러가 난다.
  → "게시판" → "%EA%B2%8C%EC%8B%9C%ED%8C%90" 으로 변환 후 URL에 넣어야 안전.

-----------------------------------------------------------------
 2-1. encodeUrl() — 문자열을 URL 안전 형식으로 변환
-----------------------------------------------------------------

  public String encodeUrl(String str) {
      if (str == null) return null;
      try {
          str = URLEncoder.encode(str, StandardCharsets.UTF_8.name());
      } catch (UnsupportedEncodingException e) {
          e.printStackTrace();
      }
      return str;
  }

  사용 예:
    "안녕"      → "%EC%95%88%EB%85%95"
    "hello"     → "hello" (영문은 그대로)
    "Java 공부" → "Java+%EA%B3%B5%EB%B6%80"

  BoardController에서 사용:
    query = "schType=" + schType + "&kwd=" + myUtil.encodeUrl(kwd);
    → 검색어를 URL에 붙일 때 인코딩해서 붙임

-----------------------------------------------------------------
 2-2. decodeUrl() — URL 형식을 원래 문자열로 복원
-----------------------------------------------------------------

  public String decodeUrl(String str) {
      Pattern pattern = Pattern.compile(".*%[0-9a-fA-F]{2}.*");
      if (str == null) return null;
      try {
          if (!str.contains("%")) return str;  // % 없으면 디코딩 불필요 (성능 최적화)
          if (pattern.matcher(str).matches())
              return URLDecoder.decode(str, StandardCharsets.UTF_8.name());
      } catch (...) { ... }
      return str;
  }

  사용 예:
    "%EC%95%88%EB%85%95" → "안녕"

  BoardController에서 사용:
    kwd = myUtil.decodeUrl(kwd);  // 검색어를 받자마자 첫 번째로 디코딩

  ★ 정규표현식 포인트:
    ".*%[0-9a-fA-F]{2}.*"
    → % 뒤에 16진수 2자리가 붙은 형태인지 검사
    → "%" 가 있어도 "%XX" 형식이 아니면 디코딩 하지 않음 (에러 방지)

 [3] HTML 태그 처리
====================================================================

-----------------------------------------------------------------
 3-1. removeHtmlTag() — HTML 태그 제거
-----------------------------------------------------------------

  public String removeHtmlTag(String str) {
      if (str == null || str.length() == 0) return "";
      String regex = "<(/)?([a-zA-Z]*)(\\s[a-zA-Z]*=[^>]*)?(\\s)*(/)?>";
      return str.replaceAll(regex, "");
  }

  사용 예:
    "<b>안녕</b>" → "안녕"
    "<p class='x'>내용</p>" → "내용"

  언제 쓰나?
  → 게시물 본문 미리보기(목록에서 요약 표시)할 때 태그 빼고 텍스트만 보여줄 때.

-----------------------------------------------------------------
 3-2. getImgSrc() — img 태그의 src 주소만 추출
-----------------------------------------------------------------

  public List<String> getImgSrc(String html) {
      List<String> result = new ArrayList<>();
      String regex = "<img[^>]*src=[\"']?([^>\"']+)[\"']?[^>]*>";
      Pattern pattern = Pattern.compile(regex);
      Matcher matcher = pattern.matcher(html);
      while (matcher.find())
          result.add(matcher.group(1));  // src 값만 리스트에 추가
      return result;
  }

  사용 예:
    입력: "<img src='/upload/1.jpg'><img src='/upload/2.png'>"
    결과: ["/upload/1.jpg", "/upload/2.png"]

  언제 쓰나?
  → 게시물 삭제 시 본문에 첨부된 이미지 파일도 함께 삭제할 때.

 [4] XSS 방어 — htmlSymbols()
====================================================================

  XSS(Cross-Site Scripting)란?
  → 게시판에 "<script>alert('해킹')</script>" 라고 입력하면
    다른 사람이 볼 때 자바스크립트가 실행되는 보안 공격.

  public String htmlSymbols(String str) {
      if (str == null || str.length() == 0) return "";
      str = str.replaceAll("&", "&amp;");  // ← 반드시 & 먼저!
      str = str.replaceAll("\"", "&quot;");
      str = str.replaceAll(">", "&gt;");
      str = str.replaceAll("<", "&lt;");
      str = str.replaceAll(" ", "&nbsp;");
      str = str.replaceAll("\n", "<br>");
      return str;
  }

  변환 대응표:
  ┌──────────┬──────────┬────────────────────────────────────┐
  │ 원래 문자 │ 변환 후   │ 이유                                │
  ├──────────┼──────────┼────────────────────────────────────┤
  │ &        │ &amp;    │ 다른 엔티티 변환에 영향 → 가장 먼저  │
  │ "        │ &quot;   │ 속성값 내 문자열 종료 방지            │
  │ >        │ &gt;     │ 태그 끝 기호 무력화                  │
  │ <        │ &lt;     │ 태그 시작 기호 무력화 (XSS 핵심)     │
  │ 공백     │ &nbsp;   │ HTML에서 공백 여러 개 표시           │
  │ \n(엔터) │ <br>     │ 줄바꿈을 브라우저에서 보이게          │
  └──────────┴──────────┴────────────────────────────────────┘

  ★ & 를 가장 먼저 변환하는 이유:
    만약 < 를 먼저 변환하면 &lt; 가 생기는데,
    그 뒤에 & 를 변환하면 &lt; 의 & 까지 &amp;lt; 로 이중 변환된다!
    그래서 반드시 & 부터 처리해야 한다.

 [5] 개인정보 마스킹 — nameMasking()
====================================================================

  public String nameMasking(String name) {
      name = name.replaceAll("\\s", "");  // 공백 제거
      int length = name.length();

      if (length < 2) return name;          // 한 글자 → 그대로
      if (length == 2) return name.charAt(0) + "*";  // 두 글자 → "홍*"

      StringBuilder masked = new StringBuilder();
      masked.append(name.charAt(0));
      for (int i = 1; i < length - 1; i++)
          masked.append("*");
      masked.append(name.charAt(length - 1));
      return masked.toString();
  }

  변환 예:
  ┌──────────┬──────────────────────────────┐
  │ 원래 이름 │ 마스킹 결과                   │
  ├──────────┼──────────────────────────────┤
  │ 김        │ 김 (그대로)                   │
  │ 김철      │ 김*                           │
  │ 강명철    │ 강*철                          │
  │ 홍길동이  │ 홍**이                         │
  └──────────┴──────────────────────────────┘

  → 개인정보 보호법 대응: 이름 전체 노출 대신 마스킹 처리

 [6] 이메일 유효성 검사 — isValidEmail()
====================================================================

  public boolean isValidEmail(String email) {
      if (email == null) return false;
      boolean b = Pattern.matches(
          "[\\w\\~\\-\\.]+@[\\w\\~\\-]+(\\.[\\w\\~\\-]+)+",
          email.trim()
      );
      return b;
  }

  정규표현식 해설:
  ┌─────────────────────────┬──────────────────────────────────┐
  │ 패턴                     │ 의미                              │
  ├─────────────────────────┼──────────────────────────────────┤
  │ [\\w\\~\\-\\.]+         │ @ 앞: 영문자, 숫자, 특수문자 1개+ │
  │ @                       │ @ 기호 필수                       │
  │ [\\w\\~\\-]+            │ @ 뒤 도메인명                     │
  │ (\\.[\\w\\~\\-]+)+      │ .com, .co.kr 같은 최상위 도메인  │
  └─────────────────────────┴──────────────────────────────────┘

  유효한 이메일:  user@example.com    → true
  유효하지 않음:  userexample.com     → false (@ 없음)
                 user@               → false (도메인 없음)
