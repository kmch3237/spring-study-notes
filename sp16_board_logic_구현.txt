  파일                             역할
  ─────────────────────────────────────────────────────
  Board.java               ← DTO (DB 컬럼 담는 그릇)
  BoardService.java        ← Service 인터페이스 (기능 목록 선언)
  BoardServiceImpl.java    ← Service 구현체 ★★★ 오늘 핵심!
  BoardMapper.java         ← Mapper 인터페이스 (SQL 연결 명세)
  bbsMapper.xml            ← 실제 SQL 작성 ★★★ 오늘 핵심!
  BoardController.java     ← URL 요청 처리 ★★★ 오늘 핵심!
  BbsList.jsp              ← 목록 화면
  BbsInsertForm.jsp        ← 등록 폼
  BbsDetail.jsp            ← 상세 + 이전/다음글
  BbsUpdateForm.jsp        ← 수정 폼

  인터페이스가 3개나 있는 이유:
  BoardService    → "어떤 기능이 있는지" 설계도
  BoardServiceImpl → "그 기능을 어떻게 하는지" 실제 구현
  BoardMapper      → "DB를 어떻게 부르는지" SQL 명세
  bbsMapper.xml    → "실제 SQL 쿼리" 작성

○ [핵심 개념] 왜 인터페이스-구현체로 분리하나?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  비유: 레스토랑 메뉴판과 주방

  BoardService (인터페이스) = 메뉴판
  → "이 식당에는 insertBoard, listBoard, deleteBoard 메뉴가 있습니다"
  → 어떻게 만드는지는 안 적혀 있음. 그냥 목록만.

  BoardServiceImpl (구현체) = 주방
  → "insertBoard는 이렇게 만든다: Mapper 호출하고, IP 세팅하고..."
  → 실제 요리(로직)가 여기에 있음.

  Controller = 웨이터
  → 손님(브라우저) 주문(URL 요청)을 받아서
  → 메뉴판(BoardService)에 있는 기능을 주방에 넘기고
  → 완성된 음식(데이터)을 손님(JSP)에게 전달

  장점:
  - 나중에 MySQL로 DB를 바꿔도 BoardServiceImpl만 바꾸면 됨
  - Controller는 BoardService 인터페이스만 알면 됨 (구현 몰라도 됨)
  - 테스트할 때 가짜(Mock) 구현체로 교체 가능

○ [IMPL 1] BoardServiceImpl.java — Service 구현체
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  위치: com.doit.app.service.BoardServiceImpl

  @Service                      ← 이 클래스는 서비스 Bean이야
  public class BoardServiceImpl implements BoardService {

      @Autowired
      private BoardMapper boardMapper;    ← Mapper를 주입받음
                                           (MyBatis가 구현체 자동 생성)

      // ━━━━━━━━━━━━━━━━━━━━━━━━━
      // 게시물 등록
      // ━━━━━━━━━━━━━━━━━━━━━━━━━
      @Override
      public void insertBoard(Board dto) throws Exception {
          boardMapper.insertBoard(dto);
          // boardMapper가 bbsMapper.xml의 <insert id="insertBoard">를 실행
      }

      // ━━━━━━━━━━━━━━━━━━━━━━━━━
      // 게시물 수정
      // ━━━━━━━━━━━━━━━━━━━━━━━━━
      @Override
      public void updateBoard(Board dto) throws Exception {
          boardMapper.updateBoard(dto);
      }

      // ━━━━━━━━━━━━━━━━━━━━━━━━━
      // 게시물 삭제
      // ━━━━━━━━━━━━━━━━━━━━━━━━━
      @Override
      public void deleteBoard(long num) throws Exception {
          boardMapper.deleteBoard(num);
      }

      // ━━━━━━━━━━━━━━━━━━━━━━━━━
      // 조회수 증가
      // ━━━━━━━━━━━━━━━━━━━━━━━━━
      @Override
      public void updateHit(long num) throws Exception {
          boardMapper.updateHit(num);
      }

      // ━━━━━━━━━━━━━━━━━━━━━━━━━
      // 게시물 전체 수 (검색 포함)
      // ━━━━━━━━━━━━━━━━━━━━━━━━━
      @Override
      public int dataCount(Map<String, Object> map) {
          return boardMapper.dataCount(map);
      }

      // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
      // 게시물 목록 조회 ★ 페이징 로직 핵심 위치!
      // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
      @Override
      public List<Board> listBoard(Map<String, Object> map) {
          // 페이지 번호와 한 페이지 크기를 받아서
          int page = (int)map.get("page");         // 현재 페이지 (1, 2, 3...)
          int size = (int)map.get("size");          // 한 페이지에 보여줄 수 (보통 10)
          int offset = (page - 1) * size;           // ★★ 핵심 계산!

          map.put("offset", offset);               // Map에 추가해서 SQL에 전달

          // 예: 3페이지, size=10 → offset = (3-1)*10 = 20
          // → SQL: OFFSET 20 ROWS FETCH FIRST 10 ROWS ONLY

          return boardMapper.listBoard(map);
      }

      // ━━━━━━━━━━━━━━━━━━━━━━━━━
      // 상세 조회
      // ━━━━━━━━━━━━━━━━━━━━━━━━━
      @Override
      public Board findById(long num) {
          return boardMapper.findById(num);
      }

      // ━━━━━━━━━━━━━━━━━━━━━━━━━
      // 이전 게시물 (검색 포함)
      // ━━━━━━━━━━━━━━━━━━━━━━━━━
      @Override
      public Board findByPrev(Map<String, Object> map) {
          return boardMapper.findByPrev(map);
      }

      // ━━━━━━━━━━━━━━━━━━━━━━━━━
      // 다음 게시물 (검색 포함)
      // ━━━━━━━━━━━━━━━━━━━━━━━━━
      @Override
      public Board findByNext(Map<String, Object> map) {
          return boardMapper.findByNext(map);
      }

  }

○ [CTRL 1] BoardController.java — 목록 조회 흐름
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  @Controller
  @RequestMapping("/board")           ← 공통 prefix. /board/list.action 처럼 쓰임
  public class BoardController {

      @Autowired
      private BoardService boardService;   ← 인터페이스로 주입받음 (구현체 몰라도 됨)

      // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
      // 게시물 목록 조회 (+ 페이징 + 검색)
      // 요청 URL: /board/list.action
      // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
      @RequestMapping("/list.action")
      public String list(
              @RequestParam(defaultValue="1") int page,
              @RequestParam(defaultValue="") String searchType,
              @RequestParam(defaultValue="") String keyword,
              Model model) throws Exception {

          int size = 10;   // 한 페이지에 보여줄 글 수 (고정값)

          // Map에 파라미터 담기
          Map<String, Object> map = new HashMap<>();
          map.put("page",       page);
          map.put("size",       size);
          map.put("searchType", searchType);
          map.put("keyword",    keyword);

          // ① 전체 게시물 수 조회 (페이지 수 계산용)
          int total = boardService.dataCount(map);

          // ② 목록 조회 (페이징 + 검색 적용)
          List<Board> list = boardService.listBoard(map);

          // ③ JSP에 전달
          model.addAttribute("list",       list);
          model.addAttribute("total",      total);
          model.addAttribute("page",       page);
          model.addAttribute("size",       size);
          model.addAttribute("searchType", searchType);
          model.addAttribute("keyword",    keyword);

          return "BbsList";   // → /WEB-INF/views/BbsList.jsp
      }

○ [CTRL 2] 게시물 상세 조회 — 조회수 증가 포함
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

      // 요청 URL: /board/detail.action?num=5
      @RequestMapping("/detail.action")
      public String detail(
              long num,                                    // URL 파라미터 num 자동 매핑
              @RequestParam(defaultValue="") String searchType,
              @RequestParam(defaultValue="") String keyword,
              @RequestParam(defaultValue="1") int page,
              Model model) throws Exception {

          // ① 조회수 1 증가 (상세 페이지 접근 시마다)
          boardService.updateHit(num);

          // ② 게시물 상세 데이터 조회
          Board dto = boardService.findById(num);

          // ③ 이전글 / 다음글 조회 (검색 중이면 검색 범위 안에서 찾음)
          Map<String, Object> map = new HashMap<>();
          map.put("num",        num);
          map.put("searchType", searchType);
          map.put("keyword",    keyword);

          Board prevDto = boardService.findByPrev(map);   // 이전글 (num 큰 것)
          Board nextDto = boardService.findByNext(map);   // 다음글 (num 작은 것)

          // ④ JSP에 전달
          model.addAttribute("dto",     dto);
          model.addAttribute("prevDto", prevDto);
          model.addAttribute("nextDto", nextDto);
          model.addAttribute("page",       page);
          model.addAttribute("searchType", searchType);
          model.addAttribute("keyword",    keyword);

          return "BbsDetail";
      }

  [ 이전글/다음글 개념 주의! ]
  게시물 번호는 최신글이 가장 높다 (시퀀스 증가)
  → "이전글" = 나보다 번호가 큰 글 중 가장 작은 것 (= 나보다 나중에 쓴 글)
  → "다음글" = 나보다 번호가 작은 글 중 가장 큰 것 (= 나보다 먼저 쓴 글)

  헷갈리는 이유:
  우리가 "이전글"이라고 하면 "이전에 쓴 글" = 번호 작은 것 이라고 생각하기 쉽지만
  일반 게시판에서는 최신글이 1페이지 위에 있으므로
  "이전" = 위에 있는 글 = 더 나중에 쓴 글 = NUM 더 큰 것
  "다음" = 아래에 있는 글 = 더 먼저 쓴 글 = NUM 더 작은 것

○ [CTRL 3] 게시물 등록 — Form과 Action 두 개!
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  ★ 등록 기능은 항상 2개 메서드 세트로 짠다!
  1) 폼을 보여주는 메서드 (GET)
  2) 폼에서 전송된 데이터를 처리하는 메서드 (POST)

      // [ 폼 보여주기 ] 요청 URL: /board/insertform.action
      @RequestMapping("/insertform.action")
      public String insertForm() throws Exception {
          return "BbsInsertForm";    // 그냥 폼 JSP만 보여주면 됨. 데이터 없음.
      }

      // [ 등록 처리 ] 요청 URL: /board/insert.action (POST)
      @RequestMapping("/insert.action")
      public String insert(
              Board dto,                      // form 데이터가 Board 객체로 자동 매핑
              HttpServletRequest request,     // IP 주소 가져오려고 request 받음
              Model model) throws Exception {

          // IP 주소를 Board에 세팅
          String ipAddr = request.getRemoteAddr();
          dto.setIpAddr(ipAddr);
          // 주의: form에서 ipAddr를 안 보내기 때문에 여기서 서버 측에서 직접 세팅!

          boardService.insertBoard(dto);

          return "redirect:/board/list.action";
          // ★ 등록/수정/삭제 후에는 반드시 redirect!
          //    그냥 return "BbsList" 하면 새로고침 시 재등록됨!
      }

  [ redirect 를 쓰는 이유 — PRG 패턴 ]
  등록 후 return "BbsList" → 사용자가 새로고침 → 같은 POST 재전송 → 중복 등록!
  등록 후 redirect:/board/list.action → 새로고침 → GET 목록만 다시 조회 → 안전!

  PRG = Post / Redirect / Get 패턴
  모든 등록/수정/삭제 액션 메서드는 반드시 redirect로 끝낼 것!

○ [CTRL 4] 게시물 수정
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

      // [ 수정 폼 보여주기 ] 요청 URL: /board/updateform.action?num=5
      @RequestMapping("/updateform.action")
      public String updateForm(
              long num,
              @RequestParam(defaultValue="") String searchType,
              @RequestParam(defaultValue="") String keyword,
              @RequestParam(defaultValue="1") int page,
              Model model) throws Exception {

          Board dto = boardService.findById(num);   // 기존 데이터 조회해서 폼에 채워줌

          model.addAttribute("dto",        dto);
          model.addAttribute("page",       page);
          model.addAttribute("searchType", searchType);
          model.addAttribute("keyword",    keyword);

          return "BbsUpdateForm";
      }

      // [ 수정 처리 ] 요청 URL: /board/update.action
      @RequestMapping("/update.action")
      public String update(
              Board dto,
              @RequestParam(defaultValue="") String searchType,
              @RequestParam(defaultValue="") String keyword,
              @RequestParam(defaultValue="1") int page,
              Model model) throws Exception {

          boardService.updateBoard(dto);

          // 수정 후 상세 페이지로 돌아감 (num과 검색 조건 그대로 유지)
          return "redirect:/board/detail.action?num=" + dto.getNum()
                 + "&page=" + page
                 + "&searchType=" + searchType
                 + "&keyword=" + keyword;
      }

○ [핵심] 페이징 로직 — 이 계산식만 외워라!
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Java에서 계산하는 3가지 값:

  int page = 현재 페이지 번호 (URL 파라미터, 기본값 1)
  int size = 10 (상수, 한 페이지당 글 수)
  int offset = (page - 1) * size   ← SQL OFFSET에 넘기는 값

  페이지 수 계산 (JSP에서 페이지 링크 만들 때):
  int totalPage = (int) Math.ceil((double) total / size)
  → total = 전체 게시물 수 (dataCount() 로 조회)
  → total이 22이고 size가 10이면:
     Math.ceil(22.0 / 10) = Math.ceil(2.2) = 3  → 총 3페이지

  페이지 번호 출력 범위 (한 번에 보여줄 페이지 수):
  int blockSize = 10   // 한 번에 1~10, 11~20 이런 식으로 묶음
  int startPage = ((page - 1) / blockSize) * blockSize + 1
  int endPage   = Math.min(startPage + blockSize - 1, totalPage)

  예: 현재 페이지 3, blockSize 10이면
  startPage = ((3-1)/10)*10 + 1 = 0*10 + 1 = 1
  endPage   = min(1+10-1, totalPage) = min(10, totalPage)

  시각화 (size=10, total=35):
  ┌────┬────────┬────────┬──────────────────────────────┐
  │page│ offset │ FETCH  │ 가져오는 글 번호             │
  ├────┼────────┼────────┼──────────────────────────────┤
  │  1 │   0    │   10   │ 35,34,33,32,31,30,29,28,27,26│
  │  2 │  10    │   10   │ 25,24,23,22,21,20,19,18,17,16│
  │  3 │  20    │   10   │ 15,14,13,12,11,10, 9, 8, 7, 6│
  │  4 │  30    │    5   │  5, 4, 3, 2, 1               │
  └────┴────────┴────────┴──────────────────────────────┘

○ [핵심] INSTR 검색 — LIKE와 비교
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  LIKE 방식:
  WHERE SUBJECT LIKE '%스프링%'
  → 와일드카드(%) 때문에 SQL Injection 위험 있음
  → MyBatis #{} 사용 시 자동 이스케이프 처리되어 % 그대로 전달됨

  INSTR 방식 (sp16에서 사용):
  WHERE INSTR(SUBJECT, #{keyword}) > 0
  → INSTR(문자열, 찾을값): 찾을값의 위치(1부터) 반환, 없으면 0
  → > 0 이면 포함, = 0 이면 미포함
  → MyBatis #{} 로 전달하면 안전

  INSTR 예시:
  INSTR('스프링 MVC 입문', '스프링')  → 1  (1번 위치에 있음)
  INSTR('스프링 MVC 입문', 'MVC')    → 5  (5번 위치에 있음)
  INSTR('스프링 MVC 입문', 'React')  → 0  (없음)

  날짜 검색 특이점 — 두 포맷 다 허용:
  TO_CHAR(REG_DATE, 'YYYY-MM-DD') = '2026-05-19'   ← 대시 있는 형식
  OR TO_CHAR(REG_DATE, 'YYYYMMDD') = '20260519'      ← 대시 없는 형식
  → 사용자가 어떻게 입력해도 검색 되도록

○ [핵심] MyBatis 동적 SQL — <where> <if>
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  문제: 검색 안 할 때는 WHERE 절 없이, 검색할 때만 WHERE 조건 붙이고 싶음

  나쁜 방법:
  WHERE 1=1
  <if test="searchType == 'all'">
      AND (INSTR(SUBJECT, #{keyword}) > 0 OR ...)
  </if>
  → WHERE 1=1 이 불필요하게 항상 실행됨

  좋은 방법 (MyBatis <where> 태그):
  <where>
      <if test="searchType == 'all'">
          (INSTR(SUBJECT, #{keyword}) > 0 ...)
      </if>
  </where>
  → <if> 조건이 하나도 true가 아니면 <where> 태그 전체가 사라짐
  → 조건이 있으면 자동으로 WHERE 키워드 붙여줌
  → AND/OR 앞에 오면 자동으로 제거해줌

  searchType 값에 따른 SQL 변화:
  ┌─────────────────────┬────────────────────────────────────────────────────┐
  │ searchType 값       │ 결과                                               │
  ├─────────────────────┼────────────────────────────────────────────────────┤
  │ "" (빈문자열/없음)  │ WHERE 절 없음 → 전체 목록                         │
  │ "all"               │ WHERE (제목 or 내용에 keyword 포함)                │
  │ "name"              │ WHERE (작성자에 keyword 포함)                      │
  │ "date"              │ WHERE (작성일 = keyword)                           │
  └─────────────────────┴────────────────────────────────────────────────────┘

  2. redirect vs forward
     redirect: 브라우저가 새 요청 → URL 바뀜 → 새로고침 안전
     forward:  서버 내부 이동   → URL 안바뀜 → 새로고침 시 재처리
     → 등록/수정/삭제 후에는 반드시 redirect!

  3. long vs int
     게시물 번호(NUM)는 long. 이론상 21억 넘을 수 있기 때문.
     조회수(HITCOUNT)는 int. 21억 넘을 일 없음.

  4. #{ipAddr} ↔ DB 컬럼 IPADDR 매핑
     Board.java 필드: ipAddr (카멜케이스)
     DB 컬럼: IPADDR (언더스코어 없음, 그냥 붙어있음)
     → MyBatis는 ipAddr → IPADDR 자동 매핑 안 해줌!
     → bbsMapper.xml에서 직접 매핑해야 함 (또는 resultMap 사용)

  5. findByPrev / findByNext 이름 반대처럼 느껴지는 것
     findByPrev: NUM > 현재  (더 나중에 쓴 글 = 화면 위쪽 글)
     findByNext: NUM < 현재  (더 먼저 쓴 글  = 화면 아래쪽 글)
