 1-1. JSTL 태그 선언 (파일 맨 위에 필수!)
-----------------------------------------------------------------

  <%@ taglib prefix="c"   uri="http://java.sun.com/jsp/jstl/core"%>
  <%@ taglib prefix="fmt" uri="http://java.sun.com/jsp/jstl/fmt"%>

  → prefix="c"   : <c:forEach>, <c:if>, <c:out> 등에 사용
  → prefix="fmt" : <fmt:formatDate> 등 날짜 포맷에 사용

-----------------------------------------------------------------
 1-2. 파비콘 더미 처리 (콘솔 404 에러 방지용)
-----------------------------------------------------------------

  <link rel="icon" href="data:;base64,iVBORw0KGgo=">

  왜 쓰나?
  → 브라우저는 사이트에 접속할 때 자동으로 서버에서 favicon.ico를 찾는다.
    그 파일이 없으면 콘솔창에 404 에러가 계속 찍힌다.
  → 위 더미 코드는 "파일 없으니까 서버에 요청하지 마" 라는 의미의
    투명한 1픽셀 이미지를 직접 데이터로 심어주는 것.
  → 개발 단계에서 콘솔 에러를 깔끔하게 없애기 위해 사용.
    (실제 배포 시에는 진짜 파비콘 파일로 교체)

-----------------------------------------------------------------
 1-3. CSS 연결 (contextPath 필수!)
-----------------------------------------------------------------

  <link rel="stylesheet" type="text/css"
        href="${pageContext.request.contextPath}/resources/css/listStyle.css">

  ★ 핵심: CSS 경로에 반드시 contextPath를 앞에 붙여야 한다.
  → ${pageContext.request.contextPath} = /app (프로젝트 루트 경로)
  → 안 붙이면 /bbs/list 요청 시 /bbs/resources/... 로 잘못 찾는다.

-----------------------------------------------------------------
 1-4. c:forEach — 게시물 반복 출력
-----------------------------------------------------------------

  <c:forEach var="dto" items="${list}" varStatus="status">
      <tr>
          <td>${dto.num}</td>
          <td class="left">
              <a href="${articleUrl}&num=${dto.num}">${dto.subject}</a>
          </td>
          <td>${dto.name}</td>
          <td>${dto.regDate}</td>
          <td>${dto.hitCount}</td>
      </tr>
  </c:forEach>

  ① var="dto"      : 반복할 때마다 현재 Board 객체를 dto라는 이름으로 씀
  ② items="${list}": Controller가 model.addAttribute("list", list)로 보낸 리스트
  ③ varStatus="status": 반복 상태 정보 객체 (아래 표 참고)

  ┌──────────────────┬───────────────────────────────────────────┐
  │ varStatus 속성   │ 의미                                       │
  ├──────────────────┼───────────────────────────────────────────┤
  │ status.index     │ 0부터 시작하는 인덱스 (0, 1, 2, ...)      │
  │ status.count     │ 1부터 시작하는 순번  (1, 2, 3, ...)       │
  │ status.first     │ 첫 번째 반복이면 true                      │
  │ status.last      │ 마지막 반복이면 true                       │
  │ status.current   │ 현재 객체 (= dto와 동일)                   │
  └──────────────────┴───────────────────────────────────────────┘

  실전 활용 예:
  → 역순 번호 계산: ${dataCount - (currentPage-1)*size - status.index}
    (1페이지 1번 게시물의 역순 번호 = 전체 개수 - 0)

-----------------------------------------------------------------
 1-5. articleUrl — 게시물 상세 링크 구성
-----------------------------------------------------------------

  Controller에서 만들어서 model에 담아 보낸 URL:
    String articleUrl = cp + "/bbs/article?page=" + currentPage;

  JSP에서 사용:
    <a href="${articleUrl}&num=${dto.num}">${dto.subject}</a>

  예시 결과: /app/bbs/article?page=1&num=5

  왜 articleUrl을 Controller에서 만드나?
  → 현재 페이지 번호(page=1)를 URL에 포함시켜야
    게시물 보다가 뒤로 가기 할 때 목록의 같은 페이지로 돌아올 수 있기 때문.

-----------------------------------------------------------------
 1-6. 페이징 출력 — 삼항연산자 활용
-----------------------------------------------------------------

  ${dataCount == 0 ? "등록된 게시물이 없습니다" : paging}

  → 게시물이 하나도 없으면 "등록된 게시물이 없습니다" 출력
  → 있으면 Controller가 만들어준 paging HTML 문자열 출력
     (paginateUtil.paging()이 반환한 <a href...> 태그들)

  ★ paging은 이미 HTML 문자열이므로 ${paging}으로 바로 출력하면 된다.

 1-8. 글쓰기 버튼 — contextPath 활용
-----------------------------------------------------------------

 [2] write.jsp — 게시물 등록/수정 폼 화면
====================================================================

┌─────────────────────────────────────────────────────────────────┐
│  write.jsp의 핵심 특징: 등록 폼과 수정 폼을 하나로 공유!          │
│                                                                 │
│  mode = "write"  → 등록 화면                                    │
│  mode = "update" → 수정 화면                                    │
│                                                                 │
│  mode 값 하나로 버튼 텍스트, 취소 텍스트, form action이 달라진다  │
└─────────────────────────────────────────────────────────────────┘

-----------------------------------------------------------------
 2-1. Controller에서 mode를 model에 담아 보낸다
-----------------------------------------------------------------

  // 등록 폼 요청 시
  @GetMapping("write")
  public String writeForm(Model model) {
      model.addAttribute("mode", "write");  ← "write"를 JSP로 전달
      return "write";
  }

  // 수정 폼 요청 시 (나중에 추가할 내용)
  @GetMapping("update")
  public String updateForm(..., Model model) {
      model.addAttribute("mode", "update"); ← "update"를 JSP로 전달
      return "write";                       ← 같은 write.jsp 재사용!
  }

-----------------------------------------------------------------
 2-2. sendOk() — JavaScript 유효성 검사 함수
-----------------------------------------------------------------

  function sendOk() {
      const f = document.boardForm;  // form name="boardForm"

      let str = f.subject.value.trim();  // 앞뒤 공백 제거
      if (!str) {
          alert("제목을 입력해야 합니다");
          f.subject.focus();
          return;  // 함수 종료 (폼 전송 안 함)
      }

      // 이름, 내용, 패스워드도 동일하게 검사...

      f.action = "${pageContext.request.contextPath}/bbs/${mode}";
      // ↑ mode가 "write"이면 /app/bbs/write (POST)
      //   mode가 "update"이면 /app/bbs/update (POST)

      f.submit();  // 최종 폼 전송
  }

  ★ 핵심 포인트
  ① trim() : 공백만 입력한 경우도 빈 값으로 처리
  ② return  : 유효하지 않으면 즉시 종료 (이후 코드 실행 안 됨)
  ③ f.action을 마지막에 설정: mode에 따라 전송 URL 동적 변경
  ④ f.submit(): 직접 폼을 제출 (type="submit" 버튼과 동일한 효과)

-----------------------------------------------------------------
 2-3. 등록완료 버튼 — 삼항연산자로 버튼 텍스트 변경
-----------------------------------------------------------------

  <button type="button" onclick="sendOk();">
      ${mode=='update' ? '수정완료' : '등록완료'}
  </button>

  <button type="button"
          onclick="location.href='${pageContext.request.contextPath}/bbs/list';">
      ${mode=='update' ? '수정취소' : '등록취소'}
  </button>

  → mode가 "update"이면 → "수정완료" / "수정취소"
  → mode가 "write"이면  → "등록완료" / "등록취소"

  ★ JSP 삼항연산자 문법:
    ${조건 ? '참일때값' : '거짓일때값'}

-----------------------------------------------------------------
 2-4. 폼 구조 요약
-----------------------------------------------------------------

  <form name="boardForm" method="post">
      제목    : <input name="subject">
      작성자  : <input name="name">
      내용    : <textarea name="content">
      패스워드: <input type="password" name="pwd">
  </form>

  → method="post" : 등록/수정은 반드시 POST (URL에 데이터 노출 방지)
  → action은 sendOk() 함수에서 동적으로 설정 (form 태그에 미리 안 씀)
  → name 속성값이 Board.java(DTO)의 필드명과 일치해야 자동 바인딩됨

  ┌────────────────┬────────────────────────────────────────────┐
  │ form name      │ Board.java 필드명                           │
  ├────────────────┼────────────────────────────────────────────┤
  │ subject        │ private String subject                     │
  │ name           │ private String name                        │
  │ content        │ private String content                     │
  │ pwd            │ private String pwd                         │
  └────────────────┴────────────────────────────────────────────┘

  ┌────────────────────┬──────────────────────────────────────┐

  ├────────────────────┼──────────────────────────────────────┤
  │ mode               │ ${mode=='update' ? '수정' : '등록'}   │
  │                    │ f.action = ".../bbs/${mode}"          │
  └────────────────────┴──────────────────────────────────────┘

 [4] 자주 하는 실수 & 체크리스트
====================================================================

  ☐ CSS 경로에 contextPath 빠뜨림
      틀림: href="/resources/css/listStyle.css"
      맞음: href="${pageContext.request.contextPath}/resources/css/listStyle.css"

  ☐ JSTL taglib 선언 빠뜨림
      → <c:forEach>가 그냥 텍스트로 출력됨

  ☐ form name 속성 누락
      → document.boardForm이 null이 돼서 sendOk() 에러 발생

  ☐ sendOk()에서 f.action 설정 안 하고 f.submit() 호출
      → action이 없어서 현재 페이지로 GET 요청됨

  ☐ 버튼에 type="submit" 쓰고 sendOk() 연결
      → 유효성 검사 전에 폼이 먼저 전송돼버림
      → 반드시 type="button" 으로 써야 sendOk() 가 먼저 실행됨

  ☐ write.jsp에서 mode를 model에 담지 않음
      → ${mode} 가 공백이 되어 action URL이 /bbs/만 됨
