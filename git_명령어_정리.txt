○ Git이란?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  버전 관리 시스템 — 파일의 변경 이력을 저장하고 관리하는 도구

  비유: 게임 세이브 포인트
  → 원하는 시점에 저장(commit)해두고
  → 잘못되면 그 시점으로 되돌아갈 수 있음
  → GitHub는 그 세이브 파일을 클라우드에 올려두는 것


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
○ Git 3가지 공간 개념 (핵심)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  [작업 폴더]  →  git add  →  [스테이지]  →  git commit  →  [로컬 저장소]  →  git push  →  [GitHub]
  Working Dir              Staging Area              Local Repo                        Remote

  작업 폴더  : 실제 내가 파일을 수정하는 곳
  스테이지   : 커밋할 파일을 임시로 모아두는 곳 (대기실)
  로컬 저장소: 내 컴퓨터 안의 Git 저장소 (세이브 포인트)
  GitHub    : 인터넷 위의 원격 저장소 (클라우드 백업)

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  # Git 사용자 정보 등록 (컴퓨터 전체 적용)
  git config --global user.name "kmch3237"
  git config --global user.email "kmch32370@gmail.com"

  # 설정 확인
  git config --list


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
○ 새 프로젝트를 GitHub에 올리는 순서 (처음 올릴 때)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  1단계: GitHub에서 새 저장소(Repository) 생성

  2단계: 로컬 폴더에서 Git 초기화
  cd 프로젝트폴더
  git init

  3단계: .gitignore 파일 만들기 (올리면 안 되는 파일 지정)
  → .gitignore 파일 참고

  4단계: 파일 스테이지에 추가
  git add .                   ← 전체 추가
  git add 파일명.txt           ← 특정 파일만 추가

  5단계: 커밋 (세이브 포인트 생성)
  git commit -m "첫 업로드"

  6단계: GitHub 저장소 연결
  git remote add origin https://github.com/kmch3237/저장소이름.git

  7단계: 업로드
  git push -u origin master


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
○ 평소 작업 흐름 (매일 쓰는 명령어)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  # 현재 상태 확인 (가장 자주 씀)
  git status
  → 어떤 파일이 수정됐는지, 스테이지에 뭐가 있는지 보여줌

  # 변경 내용 상세 확인
  git diff
  → 어떤 내용이 바뀌었는지 줄 단위로 보여줌

  # 스테이지에 추가
  git add .                   ← 변경된 파일 전체
  git add src/                ← 특정 폴더만
  git add README.md           ← 특정 파일만

  # 커밋
  git commit -m "변경 내용 설명"

  # GitHub에 올리기
  git push

  # GitHub에서 최신 내용 받아오기
  git pull

○ 집 ↔ 학원 작업 시 올바른 순서 (★ 중요)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  [ 집에서 작업 후 학원 가기 전 ]
  git add .
  git commit -m "집에서 작업한 내용"
  git push                    ← 반드시 push하고 나가기

  [ 학원 컴퓨터에서 시작할 때 ]
  git pull                    ← 반드시 pull부터
  → 이후 작업 시작

  [ 학원에서 작업 후 집 가기 전 ]
  git add .
  git commit -m "학원에서 작업한 내용"
  git push                    ← 반드시 push하고 나가기

  [ 집 컴퓨터에서 시작할 때 ]
  git pull                    ← 반드시 pull부터

  핵심: 작업 시작 → pull 먼저 / 작업 종료 → push 하고 나가기

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  # 저장소 통째로 다운로드

  # 특정 폴더에 받기
  git clone https://github.com/kmch3237/저장소이름.git C:\원하는경로

○ 이력 확인
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  # 커밋 이력 보기
  git log

  # 한 줄로 간략히 보기
  git log --oneline

  # 그래프로 보기
  git log --oneline --graph

○ 브랜치 (Branch)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  비유: 메인 스토리에서 갈라진 사이드 퀘스트
  → 브랜치에서 작업하다가 완성되면 메인(master)에 합침

  # 브랜치 목록 보기
  git branch

  # 새 브랜치 만들기
  git branch 브랜치이름

  # 브랜치 이동
  git checkout 브랜치이름

  # 만들면서 바로 이동
  git checkout -b 브랜치이름

  # 브랜치 합치기 (master에서 실행)
  git merge 브랜치이름

  # 브랜치 삭제
  git branch -d 브랜치이름

○ 실수했을 때 되돌리기
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  # 스테이지에서 빼기 (add 취소)
  git restore --staged 파일명

  # 파일 수정 취소 (저장 전 상태로 되돌리기)
  git restore 파일명

  # 마지막 커밋 메시지 수정 (push 전에만)
  git commit --amend -m "수정된 메시지"

  # 특정 커밋으로 되돌리기 (안전한 방법)
  git revert 커밋ID

  │ git clone URL               │ 저장소 처음 받아오기             │
  │ git log --oneline           │ 커밋 이력 간략히 보기            │

  │ git restore --staged 파일명 │ add 취소                         │
  │ git restore 파일명          │ 파일 수정 취소                   │
