○ Annotation이란?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  - @ 기호로 시작하는 메타데이터 (JDK 1.5부터 사용 가능)
  - 일반 주석(// /* */)은 컴파일 시 사라지지만
    Annotation은 런타임(Runtime)까지 살아있음
  - Spring이 @ 를 읽고 자동으로 빈 등록, 의존성 주입, URL 매핑 처리

  비유: 명찰(@Controller, @Repository 등)을 달면
        Spring이 알아서 역할을 인식하고 관리해줌

○ Annotation 종류 (일반 Java)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  1) Mark Annotation      : 값 없이 이름만 사용
     ex) @Override, @Deprecated

  2) Single-value Annotation : 값 하나 전달
     ex) @SuppressWarnings("unchecked")

  3) Full Annotation      : 여러 값 전달
     ex) @RequestMapping(value="/list", method=RequestMethod.GET)

  [ 내장 Annotation ]
  - @Override       : 부모 메서드를 재정의했다고 컴파일러에게 알림
  - @Deprecated     : 이 메서드는 더 이상 사용하지 말라는 표시
  - @SuppressWarnings : 경고 메시지 숨김

○ Spring 핵심 Annotation 7가지
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  ┌─────────────────┬────────────────────────────────────────────┐
  │ Annotation      │ 역할                                       │
  ├─────────────────┼────────────────────────────────────────────┤
  │ @Controller     │ 이 클래스는 MVC 컨트롤러야                  │
  │ @Service        │ 이 클래스는 서비스(비즈니스 로직)야           │
  │ @Repository     │ 이 클래스는 DAO(DB 처리)야                  │
  │ @Component      │ 그냥 Spring 빈으로 등록해줘 (범용)           │
  │ @Autowired      │ 타입(Type)으로 의존성 자동 주입              │
  │ @Resource       │ 이름(Name)으로 의존성 자동 주입              │
  │ @RequestMapping │ 이 URL 요청은 내가 처리할게                  │
  └─────────────────┴────────────────────────────────────────────┘

○ @RequestMapping
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  - URL과 메서드를 연결
  - 클래스 레벨 + 메서드 레벨 조합 가능

  예시 A) 메서드 레벨만 사용
  @Controller
  public class EmployeeController {

      @RequestMapping("/employeelist.action")
      public String list(Model model) throws Exception {
          model.addAttribute("EmployeeList", dao.list());
          return "EmployeeList";
      }

      @RequestMapping("/employeeinsert.action")
      public String insert() throws Exception {
          return "redirect:employeelist.action";
      }
  }

  예시 B) 클래스 + 메서드 레벨 조합
  @Controller
  @RequestMapping("/employee")          // 공통 prefix
  public class EmployeeController {

      @RequestMapping("/list.action")   // → /employee/list.action
      public String list() { ... }

      @RequestMapping("/insert.action") // → /employee/insert.action
      public String insert() { ... }
  }

○ @Autowired vs @Resource
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  @Autowired : 타입(Type)이 같은 빈을 찾아서 주입
               같은 타입이 2개 이상이면 에러 → @Qualifier로 해결
  @Resource  : 이름(Name)이 같은 빈을 찾아서 주입

  예시)
  @Controller
  public class EmployeeController {

      @Autowired                           // 타입으로 주입
      private IEmployeeDAO employeeDAO;

      @Resource(name="regionDAO")          // 이름으로 주입
      private IRegionDAO regionDAO;
  }

  [ @Qualifier 사용 예시 — 같은 타입이 2개일 때 ]
  @Autowired
  @Qualifier("employeeDAO")
  private IEmployeeDAO dao;

○ Model vs ModelAndView
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  방식 A — Model 파라미터 사용 (간단, 권장)
  @RequestMapping("/employeelist.action")
  public String list(Model model) throws Exception {
      model.addAttribute("EmployeeList", dao.list());
      return "EmployeeList";    // 뷰 이름만 String으로 반환
  }

  방식 B — ModelAndView 사용 (sp14 방식과 동일)
  @RequestMapping("/employeelist.action")
  public ModelAndView list() throws Exception {
      ModelAndView mav = new ModelAndView();
      mav.addObject("EmployeeList", dao.list());
      mav.setViewName("EmployeeList");
      return mav;
  }

  → 둘 다 결과는 같음. 방식 A가 코드가 더 짧아서 주로 사용.

○ sp15 컨트롤러 완성 예시 (직원 관리 전체)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  @Controller
  public class EmployeeController {

      @Autowired
      private IEmployeeDAO employeeDAO;

      @Autowired
      private IRegionDAO regionDAO;

      @Autowired
      private IPositionDAO positionDAO;

      @Autowired
      private IDepartmentDAO departmentDAO;

      // 직원 리스트
      @RequestMapping("/employeelist.action")
      public String list(HttpSession session, Model model) throws Exception {
          if (session.getAttribute("name") == null)
              return "redirect:loginform.action";
          model.addAttribute("EmployeeList", employeeDAO.list());
          return "EmployeeList";
      }

      // 직원 입력 폼
      @RequestMapping("/employeeinsertform.action")
      public String insertForm(HttpSession session, Model model) throws Exception {
          if (session.getAttribute("name") == null)
              return "redirect:loginform.action";
          if (session.getAttribute("admin") == null)
              return "redirect:logout.action";
          model.addAttribute("RegionList", regionDAO.list());
          model.addAttribute("PositionList", positionDAO.list());
          model.addAttribute("DepartmentList", departmentDAO.list());
          return "EmployeeInsertForm";
      }

      // 직원 입력 액션
      @RequestMapping("/employeeinsert.action")
      public String insert(HttpSession session, Employee employee) throws Exception {
          if (session.getAttribute("name") == null)
              return "redirect:loginform.action";
          employeeDAO.add(employee);
          return "redirect:employeelist.action";
      }

      // 직원 삭제
      @RequestMapping("/employeedelete.action")
      public String delete(HttpSession session,
                           @RequestParam("employeeId") String employeeId) throws Exception {
          if (session.getAttribute("name") == null)
              return "redirect:loginform.action";
          employeeDAO.remove(employeeId);
          return "redirect:employeelist.action";
      }
  }

○ Spring AOP 관련 Annotation (추가 개념)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  AOP = Aspect Oriented Programming (관점 지향 프로그래밍)
  = 공통 기능(로그, 보안, 트랜잭션)을 핵심 로직과 분리해서 관리

  주요 용어)
  - advice   : 공통 기능을 구현한 클래스
  - target   : advice가 적용될 객체
  - pointcut : advice가 실제로 적용될 메서드 지점
  - aspect   : advice + pointcut 묶음

  @Aspect    : 이 클래스는 AOP 공통 기능 클래스야
  @Before    : 타겟 메서드 실행 전에 실행
  @After     : 타겟 메서드 실행 후에 실행
  @Around    : 타겟 메서드 실행 전후 모두 제어

  예시)
  @Aspect
  public class LoggingAspect {

      @Before("execution(public * com.doit.app.controller.*.*(..))")
      public void beforeLog() {
          System.out.println("컨트롤러 메서드 실행 전 로그");
      }
  }
