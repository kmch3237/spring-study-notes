# 깃 사고 정리 & 대처 매뉴얼

> 학원 ↔ 집 PC 사이에서 STS 워크스페이스를 깃으로 공유하다 발생한 사고의 전말과 복구 방법, 그리고 재발 방지 가이드.

---

## 1. 오늘 무슨 일이 있었나

### 시간순 정리

| 시점 | 한 일 | 결과 |
|------|------|------|
| 어제 (집) | STS로 코드 작업 → commit → push | 원격에 집의 작업 + 집의 IDE 설정이 함께 올라감 |
| 오늘 (학원) | `git pull origin main` | 학원의 정상 STS 설정(`.metadata/`, `Servers/`)이 집의 설정으로 덮어씌워짐 |
| 결과 | STS 환경설정 초기화, `Spring Legacy Project`의 mvcproject 템플릿이 목록에서 사라짐 |

### 핵심 원인

**`.metadata/`, `Servers/`, `.settings/`, `.classpath`, `.project` 같은 IDE 설정 파일이 깃에 추적되고 있었다.**

이건 다음과 같은 문제를 일으킨다:
- PC마다 워크스페이스 경로, Tomcat 위치, JDK 경로, 폰트 등이 다 다름
- 그런데 깃으로 공유하면 한쪽 PC의 환경 설정이 다른 PC를 덮어씀
- 특히 `.metadata/`엔 mvcproject 같은 템플릿 캐시도 들어있어서 이게 망가지면 STS 신규 프로젝트 생성 메뉴까지 영향받음

## 2. 오늘 복구한 방법 (재현 가능한 절차)

### STEP 1. 현 상태 파악

```bash
git reflog
```

reflog는 **로컬 HEAD가 움직인 모든 이력**을 보여준다. pull/commit/reset/checkout 등 모든 동작이 기록되어 있어서, 어디로 되돌리면 정상이었는지 정확히 찾을 수 있다.

> 예시 출력
> ```
> b6600b1 HEAD@{0}: commit: Modify gitignore         ← 지금
> a0eee47 HEAD@{1}: pull origin main: Fast-forward    ← 🚨 망친 pull
> 4f6d8f0 HEAD@{2}: commit: 0514                     ← ✅ 마지막 정상 상태
> ```

"마지막 정상 커밋의 해시" 를 메모해둔다 (예: `4f6d8f0`).

### STEP 2. 안전망 브랜치 생성

```bash
git branch backup-before-reset
```

현재(망가진) 상태를 별도 브랜치로 보존. 나중에 살릴 작업이 있을 때 여기서 꺼낼 수 있다.

### STEP 3. STS 완전 종료 (필수)

`.metadata/.lock` 때문에 reset이 중간에 멈추는 사고 방지.

1. `File → Exit` 로 STS 종료
2. `Ctrl + Shift + Esc` → 작업 관리자 열기
3. 다음 프로세스 모두 "작업 끝내기":
   - `SpringToolSuite4.exe`
   - `javaw.exe` (여러 개일 수 있음)
   - `java.exe`
4. 그래도 lock이 남아 있으면:
   ```bash
   rm -f .metadata/.lock
   ```

### STEP 4. 정상 상태로 되돌리기

```bash
git reset --hard 4f6d8f0
```

`HEAD is now at 4f6d8f0 0514` 메시지가 나와야 성공. 이 시점에서 워킹 디렉토리가 0514 그대로 복원됨.

### STEP 5. 살릴 코드 파일이 있다면 백업 브랜치에서 꺼내오기

```bash
git checkout backup-before-reset -- "경로/파일1.java"
git checkout backup-before-reset -- "경로/파일2.jsp"
# ... 필요한 만큼
```

복원하고 싶은 파일들이 무엇이 있는지는 reset 전에 미리 확인:

```bash
# 망가진 pull로 들어온 변경 파일 목록
git diff 4f6d8f0 a0eee47 --name-only
```

### STEP 6. 커밋

```bash
git add .
git commit -m "복구: 정상 상태로 reset + 필요한 코드 복원"
```

### STEP 7. 원격 강제 덮어쓰기

```bash
git push --force-with-lease origin main
```

⚠️ `--force-with-lease`는 그냥 `--force`보다 안전한 옵션. 원격이 다른 사람에 의해 바뀌었으면 거부됨.

원격이 정상화되었다는 메시지:
```
+ a0eee47...4eb9033 main -> main (forced update)
```

### STEP 8. 동기화 확인

```bash
git pull origin main
```

`Already up to date.` 가 나오면 로컬과 원격이 같은 상태로 동기화된 것. 끝.

## 3. 재발 방지

### `.gitignore` 정비

워크스페이스 루트에 `.gitignore` 파일을 만들고 다음 내용 채우기:

```gitignore
# === Eclipse / STS 워크스페이스 ===
.metadata/
Servers/
RemoteSystemsTempFiles/

# === Eclipse 프로젝트 메타 ===
.settings/
.classpath
.project
.factorypath
.recommenders/
*.launch

# === Maven 빌드 산출물 ===
target/

# === IntelliJ ===
.idea/
*.iml

# === OS ===
.DS_Store
Thumbs.db
```

### 이미 추적 중인 파일 추적 해제 (한 번만)

`.gitignore`는 **앞으로 새로 추가될 파일만** 무시한다. 이미 추적 중인 파일은 별도로 빼야 한다:

```bash
git rm -r --cached .metadata
git rm -r --cached Servers
git rm -r --cached .settings 2>/dev/null
git rm --cached .classpath 2>/dev/null
git rm --cached .project 2>/dev/null

git add .gitignore
git commit -m ".gitignore 정비 + IDE 파일 추적 해제"
git push origin main
```

이걸 한쪽 PC에서 한 번만 하면 됨. 다른 PC에선 다음 작업 시작할 때 `git fetch origin && git reset --hard origin/main`으로 동기화하면 자동 반영.

### IDE 설정은 깃이 아니라 별도 방법으로 공유

| 동기화 대상 | 권장 방법 |
|------------|-----------|
| **소스 코드, pom.xml** | ✅ 깃 |
| **STS 환경설정**(폰트, 키바인딩, 포맷터 등) | `.epf` 파일로 export/import |
| **Tomcat 서버 설정** | PC마다 수동 설정 |
| **프로젝트 목록** | PC마다 `Import` 메뉴로 불러오기 |

`.epf` 만드는 법:
- 학원에서: `File → Export → General → Preferences` → `.epf` 파일로 저장
- USB/구글드라이브로 옮기기 (깃 X)
- 집에서: `File → Import → General → Preferences` → 그 `.epf` 불러오기

### 평소 작업 루틴

```bash
# 작업 시작 전 (항상)
git pull origin main

# 작업 끝나고 (항상)
git add .
git commit -m "오늘 작업 메시지"
git push origin main
```

이것만 지키면 PC 옮길 때 충돌 거의 안 남.

## 4. 비상 대처 체크리스트

상황별로 어떤 명령을 써야 하는지 빠르게 찾을 수 있게.

### 🚨 "pull 했더니 STS 설정이나 파일이 망가졌다"

오늘 했던 거 그대로:
```bash
git reflog                                  # 정상 커밋 해시 찾기
git branch backup-before-reset              # 안전망
# STS 완전 종료 후
git reset --hard <정상-해시>
git push --force-with-lease origin main     # 원격도 정상화
```

### 🚨 "프로젝트가 STS에서 안 보인다 (그런데 파일은 있다)"

파일 탐색기로 프로젝트 폴더 존재 확인 후:
- `File → Import → Maven → Existing Maven Projects` (Maven 프로젝트인 경우)
- 또는 `File → Import → General → Existing Projects into Workspace`

### 🚨 "git reset 도중 `.metadata/.lock` 에러"

STS가 백그라운드에서 살아있는 거. 작업 관리자에서 `javaw.exe` 모두 종료 후:
```bash
rm -f .metadata/.lock
git reset --hard <해시>     # 다시 시도
```

안 되면 PC 재부팅이 가장 깔끔.

### 🚨 "실수로 reset --hard 했는데 되돌리고 싶다"

reflog는 한동안 유지되므로 복구 가능:
```bash
git reflog
git reset --hard HEAD@{1}   # 또는 직전 해시
```

### 🚨 "force push 거부당함"

`--force-with-lease` 가 안전망 역할로 막은 것. 누가 그 사이에 push 했을 가능성. 일단:
```bash
git fetch origin
git log origin/main --oneline -5   # 누가 뭘 올렸는지 확인
```

확인한 뒤 정말로 덮어써야 한다면 `--force` 사용 (위험).

### 🚨 "Spring MVC Project 템플릿이 목록에 없다"

1. `File → New → Spring Legacy Project` 에서 `Refresh` 버튼
2. 안 되면 `Window → Preferences → Spring → Template Projects` 에서 URL 확인 후 Refresh
3. 그래도 안 되면 워크스페이스의 `.metadata/.sts/content/` 폴더 삭제 후 재시도
4. 학원 망에서 다운로드가 막혀 있는 경우 핸드폰 핫스팟으로 한 번 받기

## 5. 한 줄 교훈

> **깃은 소스 코드용이지 IDE 환경용이 아니다.**
> IDE 설정을 깃으로 공유하면, 한쪽 PC의 망가진 설정이 모든 PC를 망친다.

## 부록: 오늘 쓴 핵심 명령 모음

```bash
# 이력 보기
git reflog                              # 로컬 HEAD 이동 이력 (복구의 핵심)
git log --oneline -5                    # 커밋 히스토리
git status                              # 현재 워킹 디렉토리 상태
git diff <A> <B> --name-only            # 두 커밋 간 바뀐 파일 목록

# 브랜치
git branch <이름>                       # 현재 위치에 브랜치 생성 (안전망)
git branch                              # 브랜치 목록

# 되돌리기
git reset --hard <해시>                 # 워킹 디렉토리까지 통째로 그 시점으로
git checkout <브랜치> -- <파일경로>     # 특정 브랜치의 특정 파일만 가져오기

# 추적 제어
git rm -r --cached <폴더>               # 추적 해제 (파일은 디스크에 그대로)
git rm --cached <파일>                  # 단일 파일 추적 해제

# 원격
git fetch origin                        # 원격 정보 받기만 (병합 X)
git pull origin main                    # fetch + merge
git push origin main                    # 원격에 올리기
git push --force-with-lease origin main # 안전한 강제 푸시
```
