# 스프링 어노테이션, 비유로 쉽게 이해하기

## 0. 큰 그림: 어노테이션은 "코드에 붙이는 포스트잇"

어노테이션(`@`)은 코드 위에 붙이는 **포스트잇**이라고 생각하면 된다. 포스트잇 자체는 프로그램을 직접 실행하지 않는다. 다만 그걸 **읽는 누군가**에게 "이 코드는 이렇게 다뤄주세요"라고 알려주는 메모일 뿐이다.

읽는 사람은 상황에 따라 다르다:

- **컴파일러**가 읽는 포스트잇 → `@Override` ("이거 진짜 부모 메소드 덮어쓴 거 맞는지 확인 좀")
- **JVM**이 실행 중에 읽는 포스트잇 → 런타임까지 살아남는 어노테이션
- **스프링 컨테이너**가 읽는 포스트잇 → `@Component`, `@Autowired` 등

일반 주석(`//`, `/* */`)과 다른 점: 보통 주석은 컴파일하면 사라지지만, 어노테이션은 **설정에 따라 클래스 파일이나 실행 시점까지 살아남아서 실제로 동작에 영향을 준다.** 그래서 "메타 데이터"(데이터를 설명하는 데이터)라고 부른다.

---

## 1. 어노테이션의 종류 — 포스트잇에 적힌 정보량 차이

| 종류 | 비유 | 예시 |
|------|------|------|
| **Mark(마커) 어노테이션** | 내용 없는 빈 포스트잇, "표시"만 함 | `@Override`, `@Stateless` |
| **Single-value 어노테이션** | 한 줄짜리 메모가 적힌 포스트잇 | `@SuppressWarnings("unchecked")` |
| **Full(Multi-value) 어노테이션** | 여러 항목을 채워넣는 양식지 | `@Full(var1="a", var2="b")` |
| **Custom 어노테이션** | 내가 직접 만든 포스트잇 양식 | `public @interface TODO { String value(); }` |

> **팁:** Custom 어노테이션에서 멤버 이름을 `value`로 하면 사용할 때 이름 생략 가능(`@TODO("할일")`). 다른 이름이면 명시해야 함(`@TODO(msg="할일")`).

---

## 2. 메타 어노테이션 — "포스트잇에 붙이는 포스트잇"

어노테이션을 직접 만들 때, 그 어노테이션 자체의 성격을 정해주는 어노테이션이다. "이 포스트잇은 어디에 붙일 수 있고, 얼마나 오래 살아남는지"를 규정하는 라벨.

### `@Target` — "이 포스트잇은 어디 붙일 수 있나요?"

붙일 수 있는 위치를 제한한다.

- `TYPE` : 클래스, 인터페이스, enum
- `METHOD` : 메소드
- `CONSTRUCTOR` : 생성자
- `ANNOTATION_TYPE` : 다른 어노테이션 위

### `@Retention` — "이 포스트잇은 언제까지 살아있나요?"

| 정책 | 비유 | 생존 범위 |
|------|------|-----------|
| `SOURCE` | 회의 끝나면 버리는 메모 | 컴파일 시 삭제 |
| `CLASS` | 서랍에 넣어두지만 안 봄 | .class엔 있지만 JVM은 무시 |
| `RUNTIME` | 실행 내내 책상에 붙여둠 | 실행 중에도 유효 (스프링 어노테이션이 대부분 이것) |

---

## 3. 자바 내장 어노테이션 — 컴파일러가 읽는 포스트잇

### `@Override`
"이 메소드, 부모 거 덮어쓴 거예요"라는 표시. 컴파일러가 진짜 부모에 그런 메소드가 있는지 검사해줘서 **오타로 인한 버그**를 잡아준다.

### `@Deprecated`
"이거 이제 쓰지 마세요, 한물갔어요" 경고 딱지. 더 나은 대체 메소드가 있을 때 옛날 메소드에 붙인다.

### `@SuppressWarnings`
"이 경고는 알고 있으니 조용히 해주세요" 음소거 버튼. 값이 필요한 single-value 타입이라 `@SuppressWarnings("unchecked")`처럼 쓴다.

# 스프링 어노테이션

> 핵심 비유: **스프링 컨테이너 = 회사의 인사팀 + 총무팀.** 어노테이션은 직원과 업무에 붙이는 각종 명찰·서류·지시 메모이고, 컨테이너가 그걸 읽어서 직원(객체)을 채용·배치·연결해준다.

## 4. `@Component` — "이 사람 정직원으로 등록해주세요"

클래스에 붙이면 스프링이 그 클래스를 **빈(bean)으로 등록**한다.

**"빈으로 등록한다"는 게 무슨 뜻?**
원래는 내가 `new`로 객체를 직접 만들어 써야 한다. `@Component`를 붙이면 "이 객체는 내가 안 만들 테니 스프링 너가 만들어서 보관하고 관리해줘"라고 맡기는 것이다. 회사로 치면 프리랜서를 그때그때 부르는 게 아니라, **정직원으로 등록해서 인사팀이 관리하게 하는 것.**

작동 방식:
- XML에 `<context:component-scan base-package="패키지명">`을 설정한다 → "이 부서들 돌면서 명찰 단 사람 다 찾아서 직원 등록해"라는 지시.
- 그러면 그 패키지 하위에서 `@Component` 붙은 클래스를 자동으로 빈 등록한다.
- 빈 이름은 **클래스명 첫 글자를 소문자로** 바꾼 것 (예: `TestService` → `testService`).
- 기본 범위는 **싱글톤**(회사에 그 직원 딱 한 명). `@Scope("prototype")`를 붙이면 요청할 때마다 새로 만든다.

```java
@Component
@Scope("prototype")   // 생략하면 싱글톤
public class Test { }
```

---

## 5. `@Autowired` — "이 자리에 맞는 사람, 알아서 데려와줘"

객체 간 의존관계를 자동으로 연결(주입)한다. **타입(byType)** 으로 맞는 빈을 찾아 꽂아준다.

비유: 팀에 "개발자 한 명 필요해"라고 요청하면 인사팀이 **직무(타입)** 를 보고 맞는 사람을 데려온다.

- 위치: 생성자, 필드, 메소드 어디든 가능 (setter가 아니어도 됨)
- 문제 상황: 같은 타입 빈이 **0개면 못 찾아서 예외**, **2개 이상이면 누구를 줘야 할지 몰라서 예외**
- 옵션 `required=false` : "없어도 괜찮아요"라는 뜻. `@Autowired(required=false)` (기본값은 true)

---

## 6. `@Qualifier` — "같은 직무 여럿일 때, 콕 집어 지목"

`@Autowired`만으로는 같은 타입 빈이 여러 개일 때 곤란하다. 이때 `@Qualifier`로 **"김대리 말고 이대리"** 라고 특정 빈을 지목한다.

```java
@Autowired
@Qualifier("test")
private Test test;
```

`<bean>` 쪽에도 `<qualifier value="test"/>`를 선언해줘야 짝이 맞는다.

---

## 7. `@Resource` — "이름표 보고 데려와줘"

`@Autowired`와 하는 일은 같다(의존 객체 주입). **차이는 찾는 기준:**

- `@Autowired` → **타입(byType)** 으로 찾음 ("개발자 데려와")
- `@Resource` → **이름(byName)** 으로 찾음 ("'testDAO'라는 이름의 사람 데려와")

```java
@Resource(name="testDAO")
```

자바 6 / JEE 5에 추가된 표준 어노테이션이고 스프링 2.5부터 지원한다.

---

## 8. `@PostConstruct` — "입사하면 오리엔테이션부터"

빈이 만들어지고 의존 객체까지 다 주입된 **직후에 자동 실행**되는 초기화 메소드를 지정한다. 신입 직원이 자리 배치 끝나면 곧바로 오리엔테이션을 받는 것과 같다.

---

## 9. `@Required` — "이 칸은 필수 기입란"

setter 메소드에 붙여서 "이 프로퍼티는 반드시 설정돼야 함"을 표시한다. 안 채우면 빈 생성 시 예외가 난다. 서류의 별표(*) 필수 항목 같은 것.

```java
@Required
public void setTestDAO(TestDAO testDAO) { this.testDAO = testDAO; }
```

> ⚠️ 참고: `@Required`는 구버전 스프링 개념이고 현재는 거의 쓰이지 않는다(생성자 주입으로 대체됨). 시험·이론용으로만 알아두면 된다.

---

## 10. 어노테이션을 동작시키는 "처리기" 등록

`@Required`, `@Autowired`, `@Resource` 같은 어노테이션은 그냥 붙인다고 저절로 동작하지 않는다. 그걸 **읽고 처리해주는 담당자(BeanPostProcessor)** 가 등록돼 있어야 한다.

매번 따로 등록하기 번거로우니, XML에 이 한 줄을 넣으면 주요 처리기가 한꺼번에 등록된다:

```xml
<context:annotation-config/>
```

이게 `@Required`, `@Autowired`, `@Resource`/`@PostConstruct`/`@PreDestroy`, `@Configuration` 처리기를 모두 함께 등록해준다. "어노테이션 읽어주는 직원들 일괄 배치" 버튼인 셈.

> `<context:component-scan>`은 스캔 + 위 처리기 등록까지 겸하므로, component-scan을 쓰면 annotation-config를 따로 안 써도 된다.

# 11. Spring AOP 어노테이션 — "공통 업무를 자동으로 끼워넣기"

## 먼저 용어 정리 (비유 포함)

| 용어 | 뜻 | 비유 |
|------|-----|------|
| **advice** | 공통 기능을 구현한 코드 | 끼워넣을 공통 업무 (예: 회의록 작성) |
| **target** | advice가 적용될 객체 | 그 업무가 따라붙는 대상 (예: 모든 회의) |
| **joinpoint** | advice가 적용될 수 있는 지점 | 끼워넣을 수 있는 모든 타이밍 (회의 시작/끝 등) |
| **pointcut** | 실제로 advice를 적용한 지점 | 그중 "실제로" 끼워넣기로 정한 타이밍 |
| **advisor(aspect)** | advice + pointcut | "무엇을 + 어디에" 묶은 한 세트 |
| **weaving** | advice를 핵심 코드에 적용하는 것 | 실제로 업무를 일정에 끼워넣는 행위 |

핵심 아이디어: 로깅·트랜잭션·보안 검사처럼 **여기저기 반복되는 공통 코드**를, 핵심 로직은 건드리지 않고 바깥에서 자동으로 끼워넣는 기술이 AOP다.

## `@Aspect`
이 클래스가 "공통 업무 묶음"임을 선언한다. XML에 `<aop:aspectj-autoproxy/>`를 넣으면 스프링이 이 클래스를 읽어서 알맞은 빈에 자동으로 advice를 적용해준다.

## advice 종류 — "언제 끼워넣을지"

| 어노테이션 | 실행 시점 | 비유 |
|-----------|----------|------|
| `@Before` | 대상 메소드 실행 **전** | 회의 시작 전 출석 체크 |
| `@After` | 대상 메소드 실행 **후** (성공·실패 무관) | 회의 끝나면 무조건 정리 |
| `@AfterReturning` | 정상적으로 **리턴됐을 때** | 회의가 잘 끝났을 때 결과 보고 |
| `@AfterThrowing` | **예외가 터졌을 때** | 회의 중 사고 나면 사고 보고서 |
| `@Around` | 메소드 실행 **전·후 전체를 감쌈** | 회의 전 과정을 비서가 통제 (`proceed()`로 실제 회의 진행) |

`@Around`를 뺀 나머지는 대상 정보가 필요하면 첫 파라미터로 `JoinPoint`를 받는다.

## Pointcut 표현식 — "어디에 끼워넣을지 패턴으로 지정"

```
execution(수식어패턴 리턴타입패턴 패키지.클래스.메소드(파라미터패턴))
```

- `*` : 모든 값 (예: `get*` → get으로 시작하는 모든 메소드)
- `..` : 0개 이상 (파라미터 개수 무관 등)
- `&&`, `||` 로 여러 조건 연결

예: `execution(public * get*())` → public이고 get으로 시작하며 파라미터 없는 모든 메소드.

# 12. Spring MVC 어노테이션

업로드한 문서에는 개요만 있다 — 요지는 "어노테이션으로 설정 파일을 간결하게 하고, **뷰 페이지 ↔ 객체/메소드 매핑**을 명확히 처리한다"는 것. (`@Controller`, `@RequestMapping` 등이 대표 예시이며 문서엔 상세 내용이 없다.)

---

## 한눈에 보는 요약

- **어노테이션 = 코드에 붙이는 포스트잇.** 읽는 주체(컴파일러/JVM/스프링)에게 지시를 전달한다.
- **`@Component`** → "정직원으로 등록"(빈 등록). 컨테이너가 객체 생성·관리를 대신해줌.
- **`@Autowired`** → 타입으로 의존 객체 자동 연결 / **`@Resource`** → 이름으로 연결.
- **`@Qualifier`** → 같은 타입 여러 개일 때 특정 빈 콕 집기.
- **`@Required`** → 필수 프로퍼티 표시(구버전 개념).
- **`@PostConstruct`** → 빈 생성 직후 초기화 실행.
- **`<context:annotation-config/>`** → 어노테이션 처리기 일괄 등록.
- **AOP 어노테이션** → 반복되는 공통 코드(로깅 등)를 핵심 로직 안 건드리고 자동으로 끼워넣기.
