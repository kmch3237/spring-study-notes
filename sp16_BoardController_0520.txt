▶ 1. 컨트롤러 클래스 구조
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  @Controller                       // 스프링이 이 객체를 직접 생성·관리
  @RequestMapping("/bbs/")          // 이 컨트롤러의 모든 URL은 /bbs/ 로 시작
  public class BoardController {

      // ① 필드 선언 (소문자 = 인스턴스 변수)
      private final BoardService boardService;   // ← 소문자 b
      private final MyUtil myUtil;
      private final PaginateUtil paginateUtil;

      // ② 생성자 주입 (스프링이 빈을 여기에 꽂아 줌)
      public BoardController(BoardService boardService, MyUtil myUtil, PaginateUtil paginateUtil) {
          this.boardService  = boardService;
          this.myUtil        = myUtil;
          this.paginateUtil  = paginateUtil;
      }
  }


  ※ 의존관계 설정 방법 2가지
  ┌──────────────────────────────────────────────────────────────┐
  │ 방법 1. 필드 주입 (간단하지만 테스트 어려움)                 │
  │   @Autowired                                                  │
  │   private BoardService boardService;                          │
  │                                                               │
  │ 방법 2. 생성자 주입 (권장 — 스프링 부트 공식 스타일)         │
  │   public BoardController(BoardService boardService, ...) {    │
  │       this.boardService = boardService;                       │
  │   }                                                           │
  │   → 생성자가 1개면 @Autowired 생략 가능                      │
  │     (스프링 부트에서는 붙이면 오히려 경고)                    │
  └──────────────────────────────────────────────────────────────┘

▶ 2. @RequestMapping vs @GetMapping
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  // 긴 버전
  @RequestMapping(value = "list", method = {RequestMethod.GET, RequestMethod.POST})

  // 축약 버전 (Spring 4.3+)
  @GetMapping("list")   // GET 만
  @PostMapping("list")  // POST 만

  → 실제 코드에서는 list()가 GET/POST 둘 다 받으므로 @RequestMapping 사용
  → write 저장은 POST 만 받으므로 @PostMapping 사용

▶ 3. @RequestParam — 핵심 속성 정리
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  속성      │ 역할
  ──────────┼──────────────────────────────────────────────────
  name      │ URL 파라미터 이름 (변수명과 다를 때 명시)
  defaultValue │ 파라미터가 없을 때 쓸 기본값 (문자열로 작성)
  required  │ 필수 여부 (기본 true → 없으면 400 에러)

  // 목록 첫 진입 시: URL에 page, schType, kwd 가 없을 수도 있음
  // → defaultValue 필수

  public String list(
      @RequestParam(name="page",    defaultValue="1")   int currentPage,
      @RequestParam(name="schType", defaultValue="all") String schType,
      @RequestParam(name="kwd",     defaultValue="")    String kwd,
      Model model,
      HttpServletRequest req
  ) throws Exception { ... }

▶ 4. 페이징 + 검색 로직 5단계
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  STEP 1. 현재 데이터 개수 파악
    dataCount = boardService.dataCount(map);

  STEP 2. 전체 페이지 수 계산
    totalPage = paginateUtil.pageCount(dataCount, size);

  STEP 3. 페이지 번호 보정
    currentPage = Math.min(currentPage, totalPage);
    // 다른 사람이 삭제하여 현재 페이지 > 총 페이지가 되는 경우 방지

  STEP 4. DB 시작점(offset) 계산
    int offset = (currentPage - 1) * size;
    if (offset < 0) offset = 0;
    map.put("offset", offset);
    map.put("size", size);

  STEP 5. 해당 페이지 게시물 리스트 가져오기
    List<Board> list = boardService.listBoard(map);

  → 이후 URL 조립 + model.addAttribute 로 JSP에 전달

  String cp         = req.getContextPath();          // /app
  String listUrl    = cp + "/bbs/list";

  if (!kwd.isBlank()) {
      query = "schType=" + schType + "&kwd=" + myUtil.encodeUrl(kwd);

      articleUrl += "&" + query;

  ※ ${dto.subject} vs <c:out value="${dto.subject}">
    - ${dto.subject}     → XSS 취약 (HTML 태그 그대로 출력)
    - <c:out value=".."> → XSS 방어 (특수문자 이스케이프)
    - 실무에서는 c:out 권장, 강사님 코드는 c:out 사용

▶ 8. ★ 오늘의 실수 — 반드시 기억!!
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  【실수 1】 boardService vs BoardService
  ───────────────────────────────────────
  // 필드(인스턴스): 소문자 b
  private final BoardService boardService;

  // ❌ 잘못된 호출 (BoardService = 클래스 이름, 정적 호출 불가)
  List<Board> list = BoardService.listBoard(map);

  // ✅ 올바른 호출 (boardService = 필드 변수)
  List<Board> list = boardService.listBoard(map);

  → 클래스명과 변수명이 딱 한 글자 차이(대소문자)라 헷갈림
  → 호출할 때는 항상 "필드에 선언한 이름" 기준으로 소문자로 작성


  【실수 2】 @RequestParam name 속성
  ───────────────────────────────────────
  // ❌ name="name" → URL에 ?name=1 로 와야 동작함 (currentPage 아님)
  @RequestParam(name="name", defaultValue="1") int currentPage

  // ✅ URL의 파라미터명과 name 속성을 정확히 일치시켜야 함
  @RequestParam(name="page", defaultValue="1") int currentPage
  // (URL: ?page=2 형태로 넘어옴)

  → name = "URL에서 넘어오는 파라미터 이름"
  → 변수명(currentPage)은 자바에서만 쓰는 이름, URL과 무관


  【실수 3】 schType, kwd 에 defaultValue 누락
  ───────────────────────────────────────
  // ❌ 목록 첫 진입 시 ?schType, ?kwd 없이 들어옴 → 400 에러
  @RequestParam(name="schType") String schType

  // ✅ 검색 없을 때도 동작하게 기본값 필수
  @RequestParam(name="schType", defaultValue="all") String schType
  @RequestParam(name="kwd",     defaultValue="")    String kwd

▶ 9. 흐름 요약 (요청 → 응답)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  브라우저 → GET /bbs/list?page=1
       ↓
  BoardController.list()
    - @RequestParam으로 page, schType, kwd 받음
    - Map에 검색 조건 담기
    - boardService.dataCount(map) → 총 건수
    - paginateUtil.pageCount() → 총 페이지
    - boardService.listBoard(map) → 게시물 리스트
    - paginateUtil.paging() → 페이징 HTML 문자열
    - model.addAttribute() → JSP에 전달
    - return "list" → list.jsp 렌더링
       ↓
  list.jsp → 브라우저 화면 출력
